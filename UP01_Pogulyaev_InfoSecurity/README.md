**Тема:** «Проектирование и разработка базы данных для системы управления информационной безопасностью организации»  
**Исходная основа интерфейса:** https://github.com/Antailin/AMTech_UP_01

## Назначение

WPF-приложение предназначено для учёта информационных активов, инцидентов, рисков, политик безопасности и событий аудита. Реализованы две роли: «Пользователь» и «Администратор».

## Функциональность

- авторизация с разграничением ролей и регистрация пользователей;
- хэширование паролей SHA-256;
- капча после трёх неверных попыток входа, запрет копирования и вставки;
- смена пароля с проверкой текущего пароля;
- просмотр инцидентов пользователем, поиск, фильтрация и сортировка;
- добавление, редактирование и удаление записей администратором в восьми таблицах;
- поиск, фильтрация и сортировка в таблицах администратора;
- проверка обязательных полей, диапазонов, форматов и связанных ID;
- подтверждение удаления и выхода, каскадное удаление связанных записей;
- диаграмма распределения инцидентов по статусам;
- экспорт инцидентов в DOCX, PDF и XLSX через Microsoft Office;
- основной и альтернативный словари стилей, сохранение выбранной темы;
- единый шрифт, размеры кнопок, плейсхолдеры и всплывающие подсказки;
- журналирование действий пользователей.

## Структура базы данных

1. `Users` — учётные записи и роли.
2. `Departments` — подразделения организации.
3. `Employees` — сотрудники и их связь с подразделениями и учётными записями.
4. `SecurityAssets` — защищаемые информационные активы.
5. `SecurityIncidents` — инциденты информационной безопасности.
6. `RiskAssessments` — оценки рисков и меры реагирования.
7. `SecurityPolicies` — внутренние политики безопасности.
8. `AuditEvents` — журнал действий пользователей.

Связи: подразделение содержит сотрудников, активы и политики; актив связывается с инцидентами и оценками рисков; пользователь назначается ответственным за инцидент и создаёт события аудита. Для зависимых сущностей настроено каскадное удаление.

## Требования

- Windows 10/11;
- Visual Studio 2022 с рабочей нагрузкой «Разработка классических приложений .NET»;
- .NET Framework 4.8 Developer Pack;
- SQL Server Express или другой локальный экземпляр SQL Server;
- SQL Server Management Studio для выполнения скрипта;
- Microsoft Word и Excel для экспорта.

## Запуск

1. Откройте `db/schema.sql` в SSMS и выполните скрипт целиком. Он создаёт базу `DB_Pogulyaev_InfoSecurity`, восемь таблиц, ограничения, индексы и тестовые данные.
2. Откройте решение `UP01_Pogulyaev_InfoSecurity.sln` в Visual Studio.
3. В `App.config` проверьте параметр `data source`. По умолчанию указан `.\SQLEXPRESS`. Для LocalDB замените его на `(localdb)\MSSQLLocalDB`.
4. Восстановите пакеты NuGet и соберите решение в конфигурации Debug или Release.
5. Запустите приложение.

## Учётные записи для проверки

| Роль | Логин | Пароль |
|---|---|---|
| Администратор | `admin` | `Admin2026` |
| Пользователь | `user` | `User2026` |
| Пользователь | `auditor` | `Auditor2026` |

Пароли в базе хранятся только в виде SHA-256-хэшей. После проверки рекомендуется сменить пароли через приложение.

## Структура решения

- `Models.cs` — сущности и контекст Entity Framework 6;
- `Core.cs` — текущий пользователь, контекст, авторизация и сообщения;
- `SecurityHelper.cs` — хэширование и проверка паролей;
- `CaptchaHelper.cs` — генерация и проверка капчи;
- `ThemeManager.cs` — переключение и сохранение темы;
- `Pages/` — авторизация, регистрация, роли, таблицы и диаграммы;
- `Controls/` — универсальная форма редактирования;
- `Themes/` — общие стили и два словаря оформления;
- `ExportService.cs` — выгрузка DOCX, PDF и XLSX;
- `db/schema.sql` — создание и заполнение базы данных;
- `res/` — ресурсы приложения.

5. Проверить поиск, фильтрацию, сортировку и диаграмму.
6. Сформировать DOCX, PDF и XLSX.
7. Сменить тему, перезапустить приложение и убедиться, что выбор сохранился.
