## 2 Проектирование базы данных

### 2.1 Структура базы данных

База `DB_Pogulyaev_InfoSecurity` содержит восемь связанных таблиц. Первичные ключи реализованы столбцами `ID` с `IDENTITY(1,1)`. Для ускорения типовых запросов созданы индексы по внешним ключам и статусу инцидента.

| `Employees` | Сотрудники организации | `FIO`, `Position`, `Email`, `DepartmentID`, `UserID` |

### 2.2 Связи и ограничения

- `Departments → Employees`, `SecurityAssets` и `SecurityPolicies`: связь «один ко многим» с каскадным удалением зависимых записей.
- `SecurityAssets → SecurityIncidents` и `RiskAssessments`: связь «один ко многим» с каскадным удалением.
- `Users → AuditEvents`: связь «один ко многим» с каскадным удалением событий пользователя.
- `Users → Employees` и `Users → SecurityIncidents`: необязательные связи без каскадного удаления, предотвращающие множественные пути каскада в SQL Server.
- `Login` и `InventoryNumber` имеют ограничения уникальности.
- `Role` принимает значения `User` или `Admin`; `Status` — «Новый», «В работе», «Решён» или «Закрыт».
- `Criticality`, `Severity`, `Probability` и `Impact` ограничены диапазоном от 1 до 5.

В модели Entity Framework те же правила заданы атрибутами DataAnnotations и fluent-конфигурацией в `OnModelCreating`. Инициализатор базы отключён, поэтому приложение работает со схемой, созданной SQL-скриптом, и не изменяет её самостоятельно.

## 3 Реализация WPF-приложения

### 3.1 Архитектура решения

Главное окно `MainWindow` разделено на верхнюю панель навигации, центральный `Frame` для загрузки страниц и нижнюю панель с информацией о варианте и текущим временем. Заголовок окна и текст верхней панели динамически формируются из свойства `Title` текущей страницы.

Класс `InfoSecurityEntities` является единой точкой описания модели. Метод `Core.CreateContext()` создаёт контекст для каждой операции, что предотвращает накопление устаревших сущностей. Текущий пользователь хранится в `Core.CurrentUser`. Действия после входа записываются через `AuditService` в таблицу `AuditEvents`.

```csharp
public static InfoSecurityEntities CreateContext()
{
    return new InfoSecurityEntities();
}

public static bool Authenticate(string login, string password)
{
    string hash = SecurityHelper.GetHash(password);
    using (var db = CreateContext())
    {
        CurrentUser = db.Users.AsNoTracking()
            .FirstOrDefault(u => u.Login == login &&
                u.PasswordHash == hash && u.IsActive);
        return CurrentUser != null;
    }
}
```

### 3.2 Авторизация, регистрация и защита паролей

Авторизация выполняется отдельным методом `Core.Authenticate`. Пароль не сравнивается в открытом виде: введённое значение хэшируется алгоритмом SHA-256, после чего сравнивается 64-символьное шестнадцатеричное представление хэша. Учитывается признак активности учётной записи.

```csharp
public static string GetHash(string password)
{
    using (var algorithm = SHA256.Create())
    {
        byte[] bytes = algorithm.ComputeHash(Encoding.UTF8.GetBytes(password));
        return string.Concat(bytes.Select(x => x.ToString("X2")));
    }
}
```

После трёх неуспешных попыток панель авторизации заменяется панелью капчи. `CaptchaHelper` формирует шесть символов из набора без визуально похожих букв и цифр. Копирование, вырезание и вставка в полях капчи отменяются обработчиком `CommandManager.PreviewExecuted`.

При регистрации проверяются заполнение полей, уникальность логина, совпадение паролей и формат пароля. Допускаются английские буквы и цифры; минимальная длина — шесть символов, хотя бы одна цифра обязательна. Новая учётная запись получает роль `User`. Права `Admin` назначаются администратором через таблицу пользователей.

Смена пароля доступна с отдельной страницы. Перед сохранением проверяются логин и текущий пароль, затем выполняются стандартные проверки нового пароля и его подтверждения.

### 3.3 Функции пользователя и администратора

`UserPage` загружает инциденты вместе с названиями активов и ФИО ответственных. Поиск выполняется по названию и описанию без учёта регистра. Предусмотрены фильтр по статусу, четыре режима сортировки, очистка условий и повторная загрузка данных. Пользователь не может изменять записи.

`AdminPage` открывает восемь таблиц, диаграмму и команды экспорта. `TablePage` используется повторно для всех сущностей: столбцы и списки сортировки создаются по метаданным типа, а характерное поле используется для фильтрации. Это исключает дублирование однотипного кода.

`EntityEditorWindow` создаёт форму добавления или редактирования. Поддерживаются текстовые, числовые, логические, даты и необязательные значения. Перед сохранением выполняются преобразование типов, проверка DataAnnotations и проверка существования связанных ID. Для пользователя предусмотрено отдельное поле пароля, значение которого сохраняется только в виде хэша.

Удаление выполняется после подтверждения и сопровождается предупреждением о каскадных связях. Текущая учётная запись администратора защищена от удаления. Выход из приложения и выход из учётной записи также требуют подтверждения.

### 3.4 Диаграммы и экспорт

`DashboardPage` группирует инциденты по статусам непосредственно в SQL-запросе Entity Framework. Результат передаётся в `Series` элемента `Chart`. Доступны столбчатая диаграмма, гистограмма, круговая и кольцевая диаграммы, линейный график.

```csharp
var data = db.Incidents.GroupBy(x => x.Status)
    .Select(x => new { Status = x.Key, Count = x.Count() }).ToList();
series.Points.Clear();
foreach (var item in data)
    series.Points.AddXY(item.Status, item.Count);
```

`ExportService` формирует документы из актуального списка инцидентов. В Word создаются заголовок, дата, ФИО сотрудника, таблица и номера страниц. PDF сохраняется средствами Word через `ExportAsFixedFormat`. В Excel создаются отформатированный заголовок, восемь столбцов и автоматически подбираемая ширина. Для экспорта требуется установленный Microsoft Office.

### 4.2 Собственный словарь стилей

Альтернативная тема `PurpleDictionary.xaml` использует фиолетовые акценты `#7B3FE4` и `#2E1A5C`, светлый фон `#F1EAFF` и шрифт Segoe UI. Общие размеры и шаблоны элементов вынесены в `CommonStyles.xaml`, поэтому при смене темы сохраняются единые размеры кнопок 176×36, высота полей ввода 34 и согласованная типографика.

```csharp
public static void Toggle()
{
    Apply(CurrentTheme == DefaultTheme ? AlternativeTheme : DefaultTheme);
    SavePreference();
}

public static void Apply(string themePath)
{
    var dictionary = Application.LoadComponent(
        new Uri(themePath, UriKind.Relative)) as ResourceDictionary;
    Application.Current.Resources.MergedDictionaries.Clear();
    Application.Current.Resources.MergedDictionaries.Add(dictionary);
    CurrentTheme = themePath;
}
```

Выбранная тема сохраняется в файле настроек в локальном профиле пользователя и восстанавливается при следующем запуске. Плейсхолдеры реализованы шаблонами `HintTextBoxStyle` и `HintPasswordBoxStyle`. Для `PasswordBox` используется attached-свойство `PasswordBoxHelper.PasswordLength`, поскольку обычное свойство `Password` нельзя применять в XAML-триггере. Для полей и кнопок заданы `ToolTip` с пояснением назначения и требований к вводу.

## Приложение А. База данных

Полный скрипт создания и заполнения базы расположен в файле [`UP01_Pogulyaev_InfoSecurity/db/schema.sql`](../UP01_Pogulyaev_InfoSecurity/db/schema.sql). Он создаёт базу, восемь таблиц, ограничения, индексы и тестовые записи. При повторном выполнении существующие таблицы пересоздаются, поэтому перед запуском следует сохранить важные данные.
